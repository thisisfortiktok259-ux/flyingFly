# Flying Fly

A fruit-fly interaction demo with a small Python backend that serves:

- The app itself (`index.html`, `style.css`, `game.js`, `fly_rig.js`) from a
  fixed, allowlisted set of routes.
- Russian-language NPC chat replies generated by Google Gemini.
- 3D fly body model assets (mesh + rig metadata) mirrored from a public
  Hugging Face Space.
- A real, downsampled point cloud of fly nervous-system neuron soma
  locations, also mirrored from the same Space.

This README covers only the backend (`server.py`). It documents which
frontend files the backend serves and how, but it does not describe or
change the contents of any frontend file.

## Important disclaimers

- **The chat replies are simulated text from a language model.** They are
  character-flavored conversation, not scripted or validated game dialogue,
  and not a simulation of any real insect behavior.
- **The neuron view is a real, downsampled point cloud, not a running brain
  simulation.** `/api/neurons` returns real soma coordinates from a published
  connectome dataset. It reports where neurons physically sit, not any
  computed neural activity or firing rate. This project does not compute,
  claim, or display actual firing rates, and does not claim to be a validated
  whole-fly simulation.
- **Downloaded assets are not bundled with this repository.** The 3D body
  meshes and the neuron dataset are large binary files hosted on Hugging Face.
  The server downloads each file the first time it is requested and caches it
  locally under `.cache/` (excluded from git). The first request for a given
  asset will be slower than later ones while the cache is empty.
- **Voice/character interaction requires the Web Speech API in the browser**,
  which in turn requires a user gesture (e.g. a click or tap) before the
  browser will allow microphone access or start speech recognition/synthesis.
  This is a browser security restriction, not a backend setting; the backend
  cannot start or grant microphone access on its own.

## Data source and dataset choice: MaleCNS, not FlyWire

The neuron soma data and body mesh assets served by this backend are mirrored
from the public Hugging Face Space **`Xenova/fruit-fly-simulation`**
(`public/body/assets/` and `public/data/`), which publishes the
**MaleCNS v1.0** connectome: **166,700 neurons** spanning both the brain and
the ventral nerve cord.

This project intentionally uses **MaleCNS**, not the older **FlyWire**
dataset (which covers roughly 139,000 neurons in the brain only, with no
nerve cord). MaleCNS was chosen because it is the larger, more complete
connectome of the two and includes the nerve cord, which better supports a
full-body fly view. All neuron point data returned by this backend comes from
MaleCNS; no FlyWire data is used or mixed in.

Attribution (from the source dataset's own manifest): FlyEM / HHMI Janelia,
University of Cambridge, MRC LMB, Google Research; released under CC BY 4.0.

**Note on the metadata shape:** the published `manifest.json` lists an
ordered `metadataColumns` array for `neurons.json.gz`, but does not itself
state whether each row in that file is a JSON array (values in that column
order) or a JSON object (keyed by those column names); independent
descriptions of this file found during research were contradictory on that
point. `server.py` handles both shapes defensively and only emits a point
for a neuron when real x/y/z soma coordinates were actually parsed from the
source; it never fabricates a point.

## Requirements

- Python 3.9 or later. No third-party packages are required; the server uses
  only the Python standard library.
- A Gemini API key (for `/api/chat` only). Get one from Google AI Studio.
- Outbound internet access on first run, to fetch body assets and neuron data
  from Hugging Face, and for every `/api/chat` call to reach Gemini.

## Local setup

1. Copy the environment template and fill in your key:

   ```bash
   cp .env.example .env
   ```

   Edit `.env`:

   ```
   GEMINI_API_KEY=your-real-key-here
   GEMINI_MODEL=gemini-3.5-flash-lite
   PORT=8085
   ```

   Never commit `.env` or a real API key. `.env` is already excluded by
   `.gitignore`.

2. Run the server:

   ```bash
   python3 server.py
   ```

   It listens on `http://0.0.0.0:8085` by default (override with `PORT`).

3. Open the app in a browser at `http://localhost:8085/`. The server serves
   `index.html` at the app root (and at `/index.html`), plus `/style.css`,
   `/game.js`, and `/fly_rig.js` for the page to load; there is nothing else
   to run or build to see the app open.

4. (Optional) Run the tests:

   ```bash
   python3 -m unittest test_server.py -v
   ```

## Routes

### Frontend (fixed allowlist, not a generic static-file server)

| Route | File served | Content-Type |
|---|---|---|
| `GET /` | `index.html` | `text/html; charset=utf-8` |
| `GET /index.html` | `index.html` | `text/html; charset=utf-8` |
| `GET /style.css` | `style.css` | `text/css; charset=utf-8` |
| `GET /game.js` | `game.js` | `application/javascript; charset=utf-8` |
| `GET /fly_rig.js` | `fly_rig.js` | `application/javascript; charset=utf-8` |

Each of these five routes maps to exactly one fixed file in the project root.
There is no directory listing and no path is built from request input for
these routes, so this cannot be used to read any other file. A query string
(e.g. `/?v=123`) is accepted and ignored. Any other path, including `.env`,
`.env.example`, `server.py`, and `test_server.py`, is not on this list and
always returns a 404 JSON error; those files are never served over HTTP.

### API and asset routes

#### `GET /api/health`

Liveness check. Returns `{"status": "ok", "time": <unix timestamp>}`.

#### `POST /api/chat`

Request body:

```json
{"npc": "Зина", "message": "Привет!"}
```

- `npc` must be one of: `Зина`, `Артем`, `Григорий`, `Петрович`, `Барсик`,
  `Даня`. Any other value is rejected with a 400 JSON error.
- `message` must be a non-empty string up to 500 characters after trimming.
  The request body itself is capped at 4 KB.

Response:

```json
{"npc": "Зина", "reply": "...generated Russian text..."}
```

Errors are always JSON: `{"error": "..."}` with an appropriate HTTP status
(400 for bad input, 500 if the server has no Gemini API key configured, 502
if Gemini could not be reached or returned something unexpected). The API key
is never included in any response or log line.

Each of the six personas is a short, self-contained character sketch (there
is no additional documented backstory for these characters in this project);
adjust the persona text in `server.py` (`NPC_PERSONAS`) if richer lore is
defined later.

#### `GET /assets/body/model.json`

Proxies and caches `public/body/assets/model.json` from the
`Xenova/fruit-fly-simulation` Hugging Face Space (the fly body rig: segments,
joints, rest pose, and per-segment mesh references).

#### `GET /assets/body/meshes/<filename>.stl`

Proxies and caches one mesh file from `public/body/assets/meshes/` on the
same Space. `<filename>` is strictly validated (letters, digits, underscore,
hyphen, single `.stl` extension only); any other value, including path
traversal attempts, is rejected with a 400 error before any file access.

#### `GET /api/neurons`

Returns a deterministic sample of about 16,000 real neuron soma locations out
of the full 166,700-neuron MaleCNS dataset (every Nth neuron, in dataset
order, so the same request always returns the same sample):

```json
{
  "dataset": "MaleCNS v1.0",
  "total": 166700,
  "source": "...attribution string...",
  "points": [
    {"x": 0.12, "y": -0.4, "z": 0.03, "type": "...", "side": "...", "nt": "..."}
  ]
}
```

- `x`, `y`, `z` are the real soma coordinates, centered and uniformly scaled
  (same scale on all three axes, to preserve shape) so the whole sample fits
  roughly within `[-1, 1]` for easy rendering.
- `type`, `side`, and `nt` (neurotransmitter) are included only when present
  in the source metadata for that neuron; they are never invented.
- No synthetic or placeholder points are ever generated. If the source data
  cannot be fetched or parsed, the endpoint returns a JSON error (502)
  instead of fabricated data.

## Caching and safety notes

- All Hugging Face assets are fetched once and cached under `.cache/` next to
  `server.py`. Delete that directory to force a re-download. `.cache/` is
  excluded from git via `.gitignore`.
- Mesh filenames and all cache paths are validated against a strict allowlist
  before touching the filesystem, to prevent directory traversal.
- The server exposes only the fixed routes listed above (five static frontend
  routes plus the API/asset routes). There is no generic static-file or
  directory-listing handler, so `.env`, `server.py`, `test_server.py`, and any
  other project file are never served over HTTP.
- The server uses a threaded HTTP server with a socket timeout and a fixed
  timeout on every outbound request (to Hugging Face and to Gemini), so a
  slow or unresponsive upstream cannot hang the server indefinitely.

## Scope of this change

This backend change touches only `server.py`, `test_server.py`, `.gitignore`,
and this README. The frontend files (`index.html`, `style.css`, `game.js`,
`fly_rig.js`) are served by the new allowlisted routes above but their
contents were not modified.
